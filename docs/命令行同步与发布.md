# 命令行同步与发布

浏览器登录与 Git 命令行登录彼此独立。用官方 GitHub CLI 登录一次后，后续无需逐个上传网页文件。

## 一次性配置

在本机安装官方 gh，运行以下命令，按提示在 GitHub 页面亲自完成授权。不要将 token 或验证码发到公开仓库。

```sh
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
```

`gh auth status` 可查看登录状态，请勿使用显示令牌的选项截图或共享。授权保存在系统凭据存储中，不应写入项目。

## 同步源码

在本公开源码仓库中先拉取并查看变化，再提交明确选择的文件；不要把签名密钥、学生备份、缓存或原始私人目录加入仓库。

```sh
git pull --ff-only
git status
git add README.md package.json dist native tools docs
git commit -m "更新苹果设备支持"
git push origin main
```

首次提交如提示缺少作者，请设置你自己的 Git 提交署名；不影响网页上的账号登录身份。必要时将根 index.html、_config.yml 或模板等实际改动也加入提交。

## 发布安装包

按开发与构建.md完成各平台构建和检查后，运行 `python3 tools/package_release.py`。它打包公开源码、教师模板/AI资料、iPhone网页部署文件、题库及已有APK/EXE/DMG/ZIP，并生成SHA256。缺少原生安装包时会停止。

准备好发布说明后创建草稿，先上传所有附件，再检查并发布。以下以1.6.0为例：

```sh
git tag v1.6.0
git push origin v1.6.0
gh release create v1.6.0 --verify-tag --draft --title "生化练习室 v1.6.0" --notes-file docs/发布说明-1.6.0.md
gh release upload v1.6.0 release/github-v1.6.0/*
gh release view v1.6.0
gh release edit v1.6.0 --draft=false --latest
```

正式附件可访问后再更新 app-update.json 中的版本、说明、准确文件名与下载地址，并单独提交推送。这样旧版应用不会看到尚未上传的下载包。iPhone网站由Pages部署，不需要IPA；独立Mac包没有苹果Developer ID/公证时应在发布说明中明确说明。

Pages只需配置一次：Settings → Pages → main → root，后续推送会自动部署网页。没有服务器数据库，也不会上传学生本地记录。

官方参考：[gh auth login](https://cli.github.com/manual/gh_auth_login)、[gh release create](https://cli.github.com/manual/gh_release_create)。
